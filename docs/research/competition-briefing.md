## 5. OpenCV 5 technical facts
- Pin **`opencv-python(-headless)==5.0.0.93`** (only 5.x wheel; x86_64 + aarch64; abi3). **5.1 is due mid-October and renames DNN engine enums** (ENGINE_CLASSIC/NEW removed; EngineType AUTO=0, OPENCV=1, ORT=2) — never float the version; don't hard-code enum numbers.
- New DNN engine is **CPU-only** (CUDA/OpenCL targets silently ignored). GPU work (training, labeling) happens in PyTorch on the RTX 5090 → export ONNX → run in cv2.dnn on Graviton. Diff every model against ONNX Runtime (several op bugs fixed only on 5.x-dev: GELU-tanh, batched MatMul, Softmax opset<13…).
- Models known to run on the new engine: YOLOv8–v10/YOLO26, RT-DETR, RF-DETR, OWLv2, Grounding-DINO-T, SAM2 enc/dec, Depth-Anything-v2-S, DINOv2/v3, SigLIP, Segformer, U2Net, RTMPose, PP-OCRv3, NanoTrack, XFeat. Avoid RAFT, SAM3.
- Real 5.0 Python APIs: `cv2.ALIKED.create(onnx, cv2.ALIKED_Params())`, `cv2.DISK.create`, `cv2.LightGlueMatcher.create(onnx, thr)` (+`setPairInfo`), `cv2.ANNIndex`, `cv2.Volume` (TSDF/HashTSDF/ColorTSDF), `cv2.Odometry`, `cv2.calibrateMultiview`, `cv2.USAC_MAGSAC`/`UsacParams`, `cv2.FontFace` + Unicode putText, `cv2.mcc.CCheckerDetector`, `cv2.dnn.Tokenizer` + `enableKVCache` (LLM cameo only). Modules: calib3d → `geometry`, `calib`, `stereo`, `ptcloud` (function names unchanged).
- Gotchas: KleidiCV 3-channel INTER_LINEAR resize near scale 1 **segfaults on arm64 wheels (#29794)** → use INTER_AREA or 4-channel; warpPerspective+BORDER_REPLICATE inaccurate on ARM (#29816); TRUCO contours only via C++ RETR_LIST (Python never reaches it); hand-eye calibration missing in Python; HoughLinesP returns (N,4); np.int64 silently cast to int32; contrib wheel lacks Haar XMLs; Linux wheels can't decode AV1.
- Showcase picks: engine-explicit ONNX stack with per-layer `getPerfProfile`; ALIKED+LightGlue+MAGSAC relocalization; ANNIndex visual memory; SAM2 encoder/decoder in cv2.dnn; calibrateMultiview; ptcloud TSDF; C++ service on COOL (TRUCO + new warps).

## 8. RiverSight — recommended spec
**One-liner:** every public USGS river webcam becomes an independent, self-checking water-level gauge; a fleet agent keeps ~900 cameras honest and escalates fast rises to a human.

**Data (verified Oct 10 via NIMS API):** `GET https://api.waterdata.usgs.gov/nims/v0/cameras` lists 1,367 cameras; ~917 sent an image in the last 48 h; ~900 carry a USGS gauge ID (`nwisId`) → free ground truth from the USGS Water Data API (OGC `continuous`; free key for volume). 833 active cams are older than 90 days; 657 predate Jun 2025; archives are multi-year (e.g., Lick Creek IL has images on 2024-01-01 and 2025-07-01). 47 active gauged cams in Texas (e.g., Guadalupe Rv at Comfort [new Sep 2026], Blanco River at Wimberley, San Antonio River, Buffalo Bayou). `GET /nims/v0/listFiles?camId=…&after=…&before=…&limit=…&recent=…` returns filenames like `TX_Guadalupe_Rv_at_Comfort___2026-10-10T11-41-21Z.jpg`; images sit in public S3 `usgs-nims-images` (`/overlay/<camId>/`, `/720/<camId>/` …) [exact object path: verify]. Capture ~every 15–60 min, mostly daylight. Imagery "for the most part" public domain; flood warnings: NWS NWPS API (public). The workspace container cannot reach USGS hosts (proxy 403); fetch from Samuel's machine, the browser, or AWS.
**Pipeline:** (1) EventBridge every 15 min → SQS → Graviton worker (COOL) pulls the newest frame per camera. (2) Register to a per-site reference bank with `cv2.ALIKED` + `cv2.LightGlueMatcher` + `USAC_MAGSAC` homography; pick the reference (day/dusk/season) via DINOv2/SigLIP embeddings in `cv2.ANNIndex`; registration score = inliers/reprojection error; ORB/AKAZE ablation. (3) Waterline: small water-segmentation ONNX (pseudo-labels from SAM2 on the 5090, gauge-consistency filtering) on the new DNN engine + classical gradient profiles along K transects (Sobel/Scharr/adaptiveThreshold — COOL-accelerated). (4) **Virtual staff gauge:** per transect a 3-parameter 1-D projective map u(h) = (a·h + b)/(c·h + 1) between stage h and waterline pixel u (exact for any straight 3-D line such as a staff, pier or bank edge), fitted robustly from historical (gauge stage, pixel) pairs → camera-stage estimate + uncertainty; also invertible to **draw a forecast crest into the live image** (physics-informed video prediction). (5) QA: residual tracking vs gauge (CUSUM) → camera-moved / occlusion / gauge-suspect flags.
**Agent loop (Bedrock + Strands, OpenCV tools via MCP; Step Functions approvals):** low registration score → re-anchor / quarantine; low water-mask confidence (fog, glare, night, spider web) → fetch full-res or next frame, neighbor cam, fall back to gauge, open lens ticket; persistent camera-vs-gauge disagreement → gauge-QA ticket (ice, debris, drift); rapid rise → densify sampling, check upstream sites + NWPS forecast, render predicted crest, draft alert → human approves → SNS. Autonomous for read/recalibrate/sampling; human approval for anything external. Evaluate with fault injection (camera shift, occlusion, gauge dropout) and replays of real flood events found in the archive.
**Evaluation:** 50–100 sites × 60–90 days (~100k auto-labeled image–stage pairs); per-site temporal split + leave-site-out + few-shot onboarding (3–10 calibration points); frozen constants before the held-out read (PlumeRank-style hashes); metrics MAE/RMSE ft, % within ±0.1/±0.25 ft, coverage, rise-event precision/recall + lead time, false alerts per site-month, agent task success on injected faults; baselines: persistence, CNN regression (USGS-style EfficientNet), Canny/Hough waterline; ablations: no registration, no projective model, ORB vs ALIKED. Failure gallery: night, fog, glare, ice, snow, vegetation, flat banks, wakes.
**COOL:** fleet throughput is the point ($/camera-month for ~900 cams every 15 min on one c8g). Three-arm A/B on the same instance (COOL v3.1 vs pip 5.0.0.93 vs pip 4.12) + C++ SDK hot-path arm; provenance (`/proof` endpoint with signed instance identity doc + build info); report break-even honestly. Optional: Satya's challenge — an optimization agent that tunes the stock pipeline and compares against COOL.
**Prior art to cite and beat:** USGS/Stevens CV grant (~500 HIVIS cams), UNL GRIME AI, SAM2+LightGlue staff-gauge reading (~5 cm), pyorc LSPIV (AGPL — don't copy). Our edge: fleet scale, agentic QA, open benchmark, live endpoint.
**Kill test (by Oct 12):** 20 sites × 30 days → pass if registration succeeds on ≥90% of frames and MAE ≤0.25 ft at ≥10 sites. Fail → reframe as rise/ice/obstruction event detection, or switch to Porter.
**Long-term value:** public "HIVIS-Stage" benchmark + open toolkit; users: counties/cities adding flood cameras, DOT low-water crossings, USGS cooperators, NWS, parametric flood insurers; same engine extends to coastal cams + tide gauges, snow stakes, road ice.

## 12. Prior art (Oct 13 check) — how to frame novelty honestly
- **Camera-based water level is established.** Commercial: OTT HydroSight (<1 cm; technician-surveyed references, own hardware), Tenevia CamLevel/CamFlow, Noema (flood pixels), Hydro-STIV, Photrack. Research: Blanch & Eltner 2026 (1.3–2.7 cm MAE with RTK GCPs + 3D model), Vandaele 2021/2023 (UK river cams; 2023 = z-scored level from 95 cams, non-metric), Erfani "Eye of Horus" 2023, Sun arXiv 2605.14645 (SAM2 + LightGlue + virtual gauge, ~5 cm with gauge corners). Direct HIVIS CNN regression at 1–3 sites: Xu & Wang 2025 (12–26 cm RMSE, leaky split), Windheuser 2023, Vanden Boomen 2021.
- **USGS itself:** RISE training dataset (CC0, 20 stations, image + stage, 2016–2022); Johnson 2025 camera-stage with installed PVC references at 3 WI gauges; Stevens/CIROH $870k project building operational HIVIS CV (no stage results released yet); USGS NWDTW Jul 2026 talk comparing Tenevia/Noema vs EfficientNet-B0 regression vs staff-plate segmentation (results unpublished). GRIME-AI (UNL, Apache-2.0) has a HIVIS downloader + SAM2 but no stage output. A HackRU Oct 2025 project (RUAfloat) compared HIVIS frames to gauges with Gemini.
- **What nobody has published:** metric stage across the whole public fleet with zero on-site survey (explicit per-transect projective model fitted from gauge history), a held-out-site benchmark with baselines/ablations, a live national derived-stage endpoint, agentic QA (re-anchoring, quarantine, suspect-gauge flags, forecast overlay, human-approved alerts).
- **Claim to make:** "to our knowledge the first open system that converts an entire public river-webcam network into metric water-level instruments with no on-site survey, staff plate or target, and the first open held-out-site benchmark and live endpoint for image-derived stage on HIVIS." **Never claim** "first camera water-level system" or "first HIVIS image–stage dataset" (RISE exists) — claim first *benchmark*; include RISE sites for comparability.
- **The judge's objection** ("the gauge is already there"): answer with redundancy when gauges fail/ice/wash out, independent QA of gauges, visual context (water over a road), and future transfer to ungauged cameras — while admitting that gauge-history calibration cannot transfer to ungauged sites without a survey.
- **Innovation forecast:** 13–16/20 framed honestly; ≤10/20 if overclaimed. Expected score drivers remain Technical (eval scale + OpenCV 5 depth) and Impact.
- **Licensing:** HIVIS imagery "for the most part" public domain; some cameras may be cooperator-owned [unverified] → publish the benchmark as a manifest (image URLs + stage labels + splits), not redistributed images; blur faces/plates. Avoid "virtual staff gauge" as a product name (OTT's term); fine as a technical description.
- Contrast entry: FloodLens (flood/dry classifier, 75%, README says depth "would require additional calibration").
