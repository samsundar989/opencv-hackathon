## What the OpenCV evidence does (paired, same model, same episodes)
- Overall: **+7.5 points** (Haiku with tools minus flags only), **95 % CI −1.4 to +16.3** over 98 episodes —
  **not significant overall**. We do not claim a fleet-wide average gain.
- It is decisive where the right action depends on what the image shows: muddy-water gap-fill **+88.9**,
  re-anchoring to a banked reference **+73.3** (without registration evidence the agent never re-anchors: 0 %),
  night-frame gap-fill **+44.4**, clean view false alarms **+29.2**; false actions on clean controls halve
  (15.4 % → 7.7 %).
- It hurts where the answer is in the gauge record or in persistence rather than the image: stuck gauge
  (flatline) **−83.3**, registration loss **−21 to −25** — more tool output distracted Haiku.

## Why the LLM agents score below the rules
Most frequent failures (counts are runs; `summary.json` → `failure_modes`):
- **Haiku under-alerts:** on real rises it densifies sampling but omits the alert (rise_alert 14 runs, muddy_rise 12).
- **Out-of-range: a redundant lower bound.** All models publish `MARK_PROVISIONAL source=camera_lower_bound` (≥ the
  calibrated max) beside a fresh gauge. It is not a camera number (what D-0009 forbids), but the frozen label forbids
  any provisional value there. Post-hoc sensitivity (labelled as such; not the headline): allowing that bound moves
  Sonnet 71.4 → 78.6 %, Haiku 58.8 → 60.9 %, Haiku flags-only 51.4 → 52.7 %; rules unchanged at 93.9 %.
- **Sonnet over-escalates:** on long gauge outages it opens a "gauge suspect" ticket beside the correct gap-fill
  (stale_camera 3 runs) — prudent, but an approval email the label does not ask for (0.21 unneeded escalations /
  episode vs 0.01 for rules).
- **Missing quarantine** on synthetic camera faults and on the first cycle of a real registration loss.

## Where an LLM is better than the rules
- **Fleet triage:** Sonnet ranks the camera that needs a human first in **12/12** cycles (rules 11/12).
- **Gauge drift** (a slowly drifting gauge the rules cannot see): Sonnet 67 %, rules 0 %.
- **Rise alerts:** Sonnet 100 % on real rises and muddy rises (rules 88 % / 100 %).

## Failure handling, observed
- Malformed model output (actions sent as bare strings) occurred in 3 of 294 Haiku runs and 1 of 294 flags-only runs
  (all 4 fallbacks in the LLM arms); the strict parser raised and
  the decision fell back to the rules policy, as designed. A tolerant parser is now live
  (`POST_FREEZE_CHANGES.md`); the final arm keeps its frozen behaviour and reports the fallbacks.
- No throttling fallbacks: requests were paced at 9/min under the account's 10/min quota. This pacing is included in
  the reported LLM latency (p50 42–56 s per decision), so latency is quota-bound, not model-bound.

## Recommendation (for Cowork to rule on)
Let the deterministic, OpenCV-evidence policy take the actions — it is more accurate, cheaper and never pages a
human needlessly on clean controls — and use Claude where it measurably helps: **Sonnet 4.6 for fleet triage
ranking, for a second opinion on anything that would page a human, and for gauge-drift review**. Today the live
worker lets Haiku 4.5 decide, with rules only as the fallback.
